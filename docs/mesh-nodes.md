# 多服务器节点（主手机）

更新：2026-10-12。整体设计见服务器仓库的 [多节点设计](https://github.com/KiriKira/gsm2sip-server/blob/main/docs/mesh.md)；
旧手机一侧见 [旧手机多节点](https://github.com/KiriKira/gsm2sip/blob/main/docs/mesh.md)。

## 使用

1. 先在旧手机的 **设置 → 其他节点** 添加新服务器（例如家里的 Arch Linux，或一台 VPS）。
2. 在那台服务器上为这台主手机生成 `client` 配对码。
3. 主手机 **设置 → 服务器节点 → 添加服务器节点**，填入地址和配对码。推荐 `https://`；家庭局域网或 Tailscale 等私有网络中的节点也可用 `http://`（加入链接同样支持），此时 SIP 按服务器配置走 UDP，网络安全由你自行负责。
4. 按住 ≡ 拖动排序（读屏用户可用“提高/降低优先级”操作）。第一项优先级最高。

也可以一次加入多个节点：在每台服务器上各生成一个 `client` 配对码，用服务器仓库的
`scripts/mesh-join-link.py --role client URL=CODE ...` 生成二维码，用手机相机扫码打开
`gsm2sip://join` 链接。未配对时与第一个服务器配对，其余加为节点；已配对时全部加为节点。

点开某个节点可看详情：最近 20 次探测的可用率、中位延迟、旧手机是否在该节点注册了 SIP
（是否可通话）、最近检测时间与每次结果。

添加时主手机会检查：两台服务器都支持 `mesh` 扩展，且新服务器上能看到**同一台**旧手机
（`install_id` 一致）。任何一项不满足都会撤销刚得到的凭据并拒绝添加。

## 切换规则

| 情况 | 行为 |
|---|---|
| 当前节点连续 2 次探测失败（连不上、旧手机不在线或往返超过 3 秒） | 切到优先级顺序中第一个健康节点 |
| 更高优先级节点连续 3 次健康 | 切回（防抖，避免网络抖动来回切） |
| 正在提交短信或正在通话 | 不切换 |
| 网络变化（连上家里 Wi-Fi、切到移动数据） | 立即重新探测 |

探测由前台刷新与后台同步服务驱动，约每 25–30 秒一次，判定只依赖本机，规则在
`NodeSelectionPolicy`（纯函数，有单元测试）。

## 数据不重复

- 所有节点共用一个本地库（沿用第一个节点原有的库，升级不迁移数据）。短信按全局
  `message_id` 存一份；同一条入站短信经过几个节点都只通知一次。
- 每个节点有自己的事件游标与首轮静默同步；添加节点后会在后台静默补齐该节点的历史，
  之后切到它时只会提醒其他节点没送达过的短信。
- 网关状态与 SIM 列表含节点内的 ID 和版本号，只给写入它的节点使用；刚切换时在新节点
  同步完成前不会用旧节点的网关 ID 发送。
- 多节点下发短信由主手机铸造 `message_id`。结果不确定的短信在其他节点重试时，保留同一
  `message_id` 和 SIM，换成当前节点的网关 ID、映射版本和新的幂等键，并先写入本地库再提交；
  旧手机保证同一 `message_id` 最多执行一次。回到原节点时若服务器已有该消息
  （`MESSAGE_ID_CONFLICT`），直接采用服务器上的记录。

## 会话与后台

当前节点的会话仍在原来的加密存储里，其余节点各自加密保存；切换在同一把进程锁下交换，
不丢刷新令牌。后台同步、通知和来电开关按“配置档”绑定，切换节点不需要重新开启。
当前节点的凭据失效时，自动改用下一个仍有凭据的节点。解除配对会撤销所有节点上的凭据。

## 限制（第一阶段）

- 电话：旧手机在每个开通了 SIP 的节点注册，来电同时经各节点发出、先接者胜出；本机只在当前
  节点注册 SIP，切换节点后自动重新注册（来电接收开关按配置档保存，不需要重新打开）。多节点下
  呼出由本机铸造 `call_id`，旧手机同一 `call_id` 只拨一次。通话进行中不切换节点。
- 在一个节点发出的短信，切到其他节点后仍会用该节点自己的会话查询后续状态（约每 25 秒，
  每轮最多 30 条未结束的短信）；该节点暂时不可用时状态等它恢复后再更新。
- 经 cloudflared 暴露的家里节点只承载 HTTP/WebSocket，外网通话需要 VPS 节点。
