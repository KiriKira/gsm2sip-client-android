# Madoka 下一版本待机耗电优化计划（含无 FCM 场景）

日期：2026-10-26。状态：客户端实现已开始，见 [实施记录](standby-optimization-implementation-20261026.md)。真实节电与锁屏接听仍待真机验收。

## 1. 基线与本次结论

已 fetch 三个仓库的默认分支，固定以下审查快照；“最新合并”指这些提交，不等同于手机安装版本或线上部署版本。

| 项目 | 审查提交 | 本次相关变化 |
| --- | --- | --- |
| Madoka | `7c252c16328da712f4abcb7d01ec31b21baf43bb` | PR #26 已增加节点推送注册状态；PR #25 增加完整加密备份 |
| SoulGem | `60eeaedfc92230fa22da9a2182d794b414aa3dbc` | 仍为独立节点、RTC v1、Kyubey endpoint 推送 |
| Homura | `31f65a7d5aa7fbca7df575d73a87fcf3b018b254` | 包含音频死锁修复、主线程 watchdog、完整备份 |
| Kyubey | `28213b59122936e3b44c7f0a2d41dc8cd43e19f0` | 本次经 GitHub 重新核对 main；仍为无状态 v1 中继 |

用户提供的 **0.4.3** 统计：总计 11 小时 21 分钟，后台 11 小时 19 分钟，屏幕开启 2 分钟；唤醒锁 4 小时 43 分钟，CPU 累计 1 小时 1 分钟；移动网络 24,297 包、Wi-Fi 178,178 包。用户确认持续开启接收来电，实际通话最多几分钟，尚不清楚推送注册状态。

这是优先处理待机监听的依据，但不是各锁或各接口的归因报告。截图没有耗电 mAh、信号强度、锁 tag、逐时通话记录；CPU 是累计运行时间，不能当成持续利用率；不能凭数据包数推算请求数或承诺节电百分比。

**本计划用于 Madoka 下一版本，必须在 FCM 不可用时也改善耗电；仅依赖现有服务端/Homura 协议，不要求升级它们。** 下一版本交付请求压缩、调度拆分、无效持锁修复和可用诊断。另一个 mesh 计划是独立的远期三端项目，不作为本版本的前置条件，也不拿其未来收益替代本版本效果。

来电实时可达且无可用系统推送时，当前协议仍需要一定的监听保活。本版减少不必要工作和无网络/未监听时的持锁，不承诺把正常兼容接听的必要锁全部删掉；是否省电由无 FCM 真机对照独立验收。推送休眠、新候选资格、wake v2 与 mesh 接入已移到服务端远期计划附录。

本文接续 [上一轮方案](background-standby-power-plan.md) 与 [实施记录](background-standby-power-progress.md)。旧文中的研究来源保留其原核对日期，本次没有重新审查 Linphone/Signal 最新版本。独立的远期服务端设计见 [SoulGem mesh 计划](https://github.com/KiriKira/gsm2sip-server/blob/docs/decentralized-mesh-plan/docs/decentralized-mesh-plan-20261026.md)。

## 2. 新合并代码已经完成什么

- `PushRegistration.status()`、`NodePushStatus`、`NodeRowPresenter` 已展示注册成功、未支持、拒绝、失败和重试时间；单节点在设置中显示“推送唤醒”，多节点在节点列表和详情中显示。不要重复实现一套注册状态页面。
- “立即检测”调用 `retryNow()`，主要让未注册节点提前重试；已注册节点仍保留每日复查，**它不是一次真实 FCM 到达测试**。
- SoulGem 注册时发送 `kind=check`，Kyubey 使用 `validate_only=true`，不会投递给手机。UI 的“已注册”只能证明登记与验证成功，不能表示深度休眠下可达。
- 上轮已实现 HTTP 分类计数、ACK 持久化去重、同步合并、部分能力续租共享与后台恢复任务；继续保留。
- 新完整备份排除了 `host-push`。新增的端点代际、推送到达证明、休眠资格、网络测量也必须按设备重新建立，不能随备份恢复成“已验证”。

## 4. 分阶段实施

### M0：可解释的待机诊断，先取得可重复基线

修改 `StandbyDiagnostics`、`RtcSignalingWakeLease`、`HostBackgroundService`、`MadokaMessagingService`、`PushRegistration`，沿用现有设置和节点详情页面。

1. 按锁 tag 聚合获取次数、累计实际持有时间、最长持有时间、当前持锁原因。自动超时按 lease 截止时间计，不把失去所有权后的时间算进去；进程异常结束记录“未完整闭合区间”。
2. 按节点匿名标识、接口类别、触发原因记录真实 HTTP 次数、失败、耗时、应用层字节数；应用层字节不冒充 TCP/TLS 或系统计费流量。记录 RTC 轮询间隔、续租、WSS 重连及连接寿命。
3. 注册结果与最近收到 FCM 的时间分开显示；实际/original priority、后台服务启动失败、过期提示、补查成功单独计数。不要把近期无业务视为推送失败。
4. 增加脱敏 JSON 导出：进程/启动分段、统计区间、版本、协议、节点数、当前模式、失败原因；不导出号码、正文、token、完整 endpoint。内存累计、低频合并落盘，避免每个 poll 写日志。
5. 本版只展示现有 FCM 回调的本地接收时间/优先级与注册状态；保留“立即检测”的登记检测含义。不依赖新 nonce/回执协议，不为了检测而周期发送高优先级消息。无 FCM 时同样提供锁、请求和当前监听方式的诊断。

完成条件：用户能从应用内分辨“已登记”和“实际收到”；同一时间窗口的应用锁统计与 batterystats 对照，差异可解释。M0 不改变监听时序。

### M1：下一版必须交付的请求压缩（与 FCM 无关）

把 `STANDBY_EXPERIMENTS` 中各项拆开灰度，避免一次打开全部变量。以下为初始试验值，不是已验收发布参数。

| 调度项 | 建议策略 | 必须保留的即时触发 |
| --- | --- | --- |
| 短信兜底 | WSS 已验证活跃时 120s；失去 WSS 时回到 30s；连续失败指数退避至 300s，加抖动 | 推送、WSS 提示、网络恢复、前台手动刷新 |
| 元数据 | 缓存存在时 300s；能力结果按版本/节点缓存 | 首次配对、节点切换缺缓存、SIM 变更提示、业务返回 mapping conflict |
| 备用节点健康 | 与 RTC 续租拆开后，稳定后台 120s，最长 300s；活跃节点用已有请求结果更新健康 | 当前节点失败、网络变化、用户检测；过期健康结果不能直接当可用 |
| RTC 资格 | v1 节点仍独立续租，建议以 30s 为起始测试值并留出网络预算 | 开关变化、会话换代、节点恢复；不受慢速健康任务阻塞 |
| 历史状态 | `CrossNodeStatus` 与探测脱钩，仅有未完成记录时查询；近期任务快，长期 unknown 慢且有上限 | 推送/进入历史页；unknown 不自动重新发送或拨号 |
| WSS 心跳 | 独立实验先关闭客户端 Ping，保留服务端 20s Ping/Pong | 黑洞恢复与连接失效必须有检测途径；不要假设关闭主动 Ping 后自动具备原检测能力 |

30→120s 对应周期触发数约减少 75%，30→300s 约减少 90%，仅是这两类定时触发的理论变化。WSS、元数据缓存、去重与节点分层调度不依赖 FCM，推送不可用时同样生效。多节点资格续租和必要兼容监听锁尚在，实际总耗电必须测量。

完成条件：HTTP 计数证明减少；节点故障不等待整个慢周期才切换；关闭接听不会被 NodeMonitor 重新启用；接听、短信与新旧节点混合不回归。

### M2：无 FCM 的监听与锁优化（本版范围）

不能只在 pushReady=true 分支应用省电策略。拆分以下模式，并以实际网络/监听状态驱动，所有优化保留业务截止时间约束：

| 场景 | 本版策略 | 可靠性边界 |
| --- | --- | --- |
| FCM 不可用、WSS 健康 | 继续 WSS 即时唤醒；减少兜底空查、元数据/节点探测并合并续租 | 不依赖 FCM；丢 WSS 提示必须由兜底在 25s 来电窗口内发现 |
| FCM 不可用、WSS 不可用、HTTPS 可达 | 有界 HTTPS 轮询，复用连接/结果并减少独立续租请求；失败退避，恢复立即补查 | 保留实时接听所需的兼容锁；不能直接把来电轮询改成分钟级 |
| 明确没有默认网络，且没有活跃通话 | 暂停 RTC 网络轮询/续租，释放空闲监听锁；注册默认网络回调恢复，恢复后先声明资格再拉取 | 网络恢复回调必须在目标厂商真机验证；失败时清楚显示未连接 |
| 有网络但节点失败 | 全局协调失败退避，立即尝试有限备选；网络请求期间短锁，退避间隙释放无效锁作为独立灰度项 | 必须有系统允许的恢复机会；普通线程计时器不能保证深睡中按时唤醒。未验证前不发布会静默漏接的锁释放策略 |
| 用户关闭接听、会话撤销、服务销毁 | 统一资格与锁所有权、取消旧代际任务，NodeMonitor 不得重新 capability(true) | 活跃通话的锁由通话生命周期独立管理，不能被停监听误释放 |
| 挂断/失败后 | 及时释放媒体和监听以外的短锁；确保不会因遗留 delivered/media 状态停留在 750ms 轮询 | 增加真实终态、丢终态、进程恢复、远端挂断的回归 |

空闲轮询另设独立实验：无 FCM + WSS 健康从 8s 试验到 12s；无 FCM + 无 WSS 从 3s 试验到 5s。保留通话中 750ms 与原有操作触发的即时拉取；参数尚待请求耗时预算和漏接测试，不直接宣告发布默认值。失败退避已有行为要保留，但避免多个服务各自重试形成放大。

来电 25s 窗口内必须留出最坏轮询等待、调度延迟、请求超时、响铃及用户接听时间；若弱网测试不能满足，就保留原轮询值，先交付其他优化。8→12s 与 3→5s 仅分别减少约 33%/40% 的对应空闲轮询次数，不代表相同节电比例。

HTTP 层先记录 DNS/TLS/连接复用与请求耗时。只有证据显示反复建连时，才将相关请求迁移到按安全边界复用的 OkHttp client；复用连接池不共享跨节点 bearer/拦截器状态，保留重定向限制、超时、session generation 和刷新串行语义。不能仅因使用 HttpURLConnection 就断言每次都会新建 TCP。

### M3：版本配置和资源生命周期收口

- 把短信周期、元数据周期、节点健康周期、RTC 空闲周期、失败退避、单侧心跳分别配置，默认使用通过验收的值，不靠一个总实验开关交付所有变化。
- 合并并发 sync/wake/网络恢复，跨异步工作维持明确所有者；持锁计时按实际持有区间统计，任何退出路径都有释放或有界到期。
- 兼容现有 90s 在线资格与 20s 活跃控制租约，不新增服务器 API。
- 完整备份恢复后保留历史/配对，但重新建立网络状态和诊断分段，不把旧运行态/锁状态当当前状态。

## 6. 验收、收益判断和回退

自动化在实施时运行：复用 `PushPolicyTest`、`NodeRowPresenterTest`、`RtcSignalingWakeLeaseTest`、`HostBackgroundPolicyTest`、节点隔离和数据库测试，新增有意义的有/无 FCM 状态转换、现有协议兼容、真实请求计数、并发/进程重启、撤销与备份恢复案例。文档阶段不以旧测试结果证明新方案。

真机分别跑：单/三节点、Wi-Fi/移动网络/弱信号、Doze、VPN、无 GMS、厂商后台限制、FCM 降级/丢弃、当前节点故障、节点到 Kyubey 故障、用户关闭/恢复备份。保持设备、信号、版本、节点与系统策略一致，基线/优化各至少 8h × 3 轮，通话压力与静默功耗分开测；持续 USB 调试可能影响休眠。

| 验收项 | 门槛 |
| --- | --- |
| 兼容模式 M1 | 重复请求下降可解释；监听资格和即时恢复不退化，报告短信兜底延迟变化 |
| 无 FCM 必测 | FCM 禁用/不可用且无法取得 endpoint，分别测 WSS 正常与仅 HTTPS；不能拿有 FCM 的结果代替 |
| 无效锁 M2 | 明确无网络且无通话、用户关闭接听后，监听锁及时释放；网络恢复接听通过；正常兼容监听锁单独报告 |
| 来电 | 每个关键场景至少 30 次随机呼入，样本内无漏接，全部在有效窗口内出现；报告 P50/P95/max，不能将有限样本当生产零漏接保证 |
| 超时/冲突 | 过期不响、重复不双通知、已接听不重响、unknown 不重新拨号 |
| 功耗 | 同条件 mAh/h 或可靠能量数据与系统归因一起报告；未实测不承诺百分比 |
| 节点选择 | 原有独立节点故障后恢复新业务；健康探测降频不拖延故障切换；通话仍固定节点 |

下一版发布判定：无 FCM 的两类可联网待机场景分别报告 mAh/h、CPU、请求数、锁耗时和来电成功率；同条件重复测量应显示超出测量噪声的耗电下降。若只能证明请求减少、尚不能证明电量改善，明确标为部分验收，继续定位，不能称“无 FCM 节电已完成”。断网测试不替代正常联网待机测试。

回退开关独立：元数据、短信、健康探测、RTC 空闲周期、心跳和失败期间释锁。出现漏接、恢复不及时、用户停止后复活，即回退对应策略；保留诊断与已验证的其他优化。服务端/Homura 保持当前协议，无需等待 mesh 上线。
