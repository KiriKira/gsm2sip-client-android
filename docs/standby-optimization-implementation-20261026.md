# Madoka 下一版本耗电优化实施记录

日期：2026-10-26。分支：`feat/madoka-standby-power`。最新主线基线：`19e75e1`；同时保留已提交的 [独立客户端计划](standby-optimization-plan-20261026.md)。本次只修改 Madoka，使用现有 SoulGem/Homura 协议。

## 已实施

| 计划项 | 实际改动 |
| --- | --- |
| N1 诊断 | 设置新增“查看与导出待机统计”：中文摘要、JSON 分享；按匿名节点编号和触发原因统计 HTTP 请求/失败/耗时/应用层字节；记录 RTC/短信锁次数、累计和最长时间（按超时截止），WSS 打开/关闭次数及连接总时长、最近收到的 FCM 时间与实际/原始优先级 |
| N1 进程分段 | 每五分钟最多保存一次缓存，最多八个进程分段；不在完整备份中恢复。异常结束的尾段只算最后采样时刻，缓存被清除时不承诺历史完整；不输出 URL、号码、正文、凭据或推送端点 |
| N2 同步 | WSS 活跃时短信周期由 30s 改为 120s，WSS 不可用仍为 30s；失败退避至 300s。推送、WSS、切网仍立即补查。网关/SIM 元数据缓存由 30s 改为 300s |
| N3 节点维护 | 后台全节点健康探测由 15～30s 改为 120s；前台仍为 15s。资格续租独立工作队列，约 30s、按节点合并成功响应；慢健康探测不承担续租。RTC 失败触发受限的即时故障探测，WSS 故障/切网继续强制探测 |
| N3 开关一致性 | 健康探测不再无条件 capability(true)；独立维护读取接听偏好，关闭时撤销；若 HTTP enable 与用户关闭竞争，补发 disable。活跃呼出仍由活跃引擎拥有资格 |
| N3 历史状态 | 历史短信状态查询与健康探测拆开；无未完成记录就不请求，状态长期不变/请求失败逐级减频到 240s，发生变化恢复正常查询 |
| N4 无网络释锁 | 引擎注册默认网络回调；无默认网络且没有活跃通话时暂停空闲信令锁并跳过请求，恢复网络立即拉取并恢复资格；引擎关闭后迟到请求不能重新获取该锁。若网络回调注册失败，保留原兼容路径 |
| N4 生命周期 | 关闭监听、销毁引擎、节点替换均保留明确的锁和网络回调释放；原有媒体终态清理继续保留 |
| N5 独立实验 | 无 FCM 空闲 RTC 8→12s（有 WSS）、3→5s（无 WSS），以及仅服务端主动 Ping，均默认关闭。正常在线兼容接听的必要锁继续保留 |

上述默认改动不要求 FCM 可用。未引入 wake v2、sleep subscription 或 mesh 路由；推送休眠属于另一份远期计划。

## 参数与回退

构建属性可独立覆盖（毫秒）：

| 属性 | 默认 | 用途 |
| --- | --- | --- |
| `standbyMetadataMs` | 300000 | 网关/SIM 缓存间隔；回退 30000 |
| `standbySmsLiveMs` | 120000 | WSS 活跃时短信兜底；回退 30000 |
| `standbyNodeHealthMs` | 120000 | 后台健康探测间隔；回退 15000 |
| `standbyFailureBackoff` | true | 短信失败退避；可单独关闭 |
| `standbySlowRtc` | false | 未验收的慢速空闲 RTC 试验 |
| `standbyServerPingOnly` | false | 未验收的单侧主动心跳试验 |

原 `standbyExperiments` 属性保留以兼容已有构建调用，新的生产策略不再依赖它。通话中 750ms 轮询、15s 失联判定与服务端 20s 控制租约保持原语义。复用 HttpURLConnection 原有网络栈，未在没有连接复用测量依据时更换 HTTP 实现。

## 测试范围与现实验收

仅新增两项回归：暂停锁后恢复/关闭行为，以及无 FCM 时断网跳过请求、恢复网络立即取真实格式的来电列表。扩充已有节点测试确认健康探测不会启用接听；更新已有短信调度测试。已有 HTTP、ACK、能力去重、通话终态和会话隔离测试继续复用，没有新增组合爆炸或长期压力测试。

最终代码验证：`:app:testDebugUnitTest` 共 219 项，0 失败、0 错误、0 跳过；`:app:lintDebug` 通过，0 错误、53 项警告；`:app:assembleDebug` 通过。`git diff --check` 通过。APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

`adb devices -l` 没有连接设备，因此没有声称已达到计划中的无 FCM 节电验收。

建议实际使用验证集中在四项：

1. 无 FCM、正常 Wi-Fi 待机一夜，导出统计并比较系统电量/CPU/锁时间。
2. 无 FCM、移动网络待机，随机呼入，记录是否及时响铃。
3. 飞行模式后恢复 Wi-Fi/移动网络，确认能重新接听，断网期间不持有空闲监听锁。
4. 关闭接听及挂断后，确认状态、锁与请求频率恢复正常。

测量耗电时拔掉充电线。HTTP 请求减少不直接等价于电池耗电同比下降；当前在线兼容模式仍需信令锁，完整推送休眠另行实施。
