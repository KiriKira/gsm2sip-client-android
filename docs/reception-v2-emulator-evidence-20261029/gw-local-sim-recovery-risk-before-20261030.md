# Homura retained-SIM local recovery — before action (2026-10-30)

Read-only preflight found the GW emulator idle (`mCallState=0`, no Telecom call). Its existing local mapping is still at revision 13, slot 0, subscription 1, and is marked `UNVERIFIED`; the salted fingerprint and SIM UUID are still present locally. A read-only comparison of the local SIM UUID with Node A's sole active SIM row matched exactly. Node A remains at revision 13 with that row `active`, `identity_verified=true`, slot 0. No proposal, heartbeat, SQL write, pairing change, or call injection occurred during this preflight.

The ordinary MainActivity refresh can only observe that Android hides the ICCID fingerprint from the app UID, so it cannot safely use the existing UI proposal flow: that flow omits `existing_sim_id` for an `UNVERIFIED` local mapping and could remove the retained binding. The planned recovery is a one-shot temporary Android-test instrumentation helper that runs as the target app UID (verified before mutation) and invokes the existing production `SimRegistry.confirmMapping` for the retained SIM UUID, subscription 1, and current server revision 13. It will not adopt shell permissions, call a server API, edit SharedPreferences directly, or write SQL. Expected local result is `LOCAL_CONFIRMED` if the app still cannot read a fingerprint, otherwise `FINGERPRINT_VERIFIED`; the SIM UUID, slot, and mapping revision must remain unchanged.

After that local check, the ordinary Settings UI may enable only “后台运行”, which starts control/sync and keeps voice disabled. The four background preferences and service state will be checked, along with Node A's mapping revision and identity. Stop without enabling the service if the instrumentation is not the target app UID, if the retained UUID/slot/revision differs, or if the helper result differs from the expected binding. Stop before any call if Node A changes identity or revision, the service enables voice, or modem/Telecom is not idle.

This is a local test-emulator state repair through a production helper, not a product source change or fabricated SIM event. The helper source and temporary APK will be removed/restored after use. Recovery is reversible by the same retained-SIM local confirmation; no user data, pairing, SMS/call history, server rows, or system/root state is removed or changed.
