## Harness 修复（本次新增，均已在 lab 上验证）

1. **来电 UI 判定**：main 版 Host 没有 `CallActionActivity`，只有 `incoming-calls-v2` 通知（actions=`Decline`/`Answer`）；
   R1 版有 `CallActionActivity`。判定顺序改为「先活动、后通知」，两者都用真实点击。
2. **轮询开销**：每轮 `dumpsys window` + `dumpsys activity` + `dumpsys power` 三次 adb 调用会把 2 vCPU 的模拟器压死，
   反而错过 26 s 的响铃窗口；改为单次 `dumpsys telecom | grep`，或直接读 DB 的 `call_participants.state`（亚秒级）。
3. **`grep` 无匹配即非零退出**：`adb()` 会误抛，新增 `adb_soft()`。
4. **调用 ID 竞态**：注入后立刻查 `ORDER BY created_at DESC LIMIT 1` 会拿到上一通；必须用 `created_at >= t0` 等本通落地。
5. **`dumpsys telecom` 截断**：整份 dump 近 800 行且可能 `Broken pipe`，断言改在设备上 `grep -m1`。
6. **UI 前置**：残留的 `CallActionActivity`（`通话已结束 / 关闭`）会让后续 `设置` 点击失效，脚本开头先关闭它；
   冷启动后要等 `设置` 导航节点出现再点，固定 `sleep 12` 不够。
7. **滚动定位**：`后台来电接收` 开关在设置页底部区域，先 3 次下滑到底、再 1 次上滑即稳定可见，
   逐次全量搜索反而因为滚动位置漂移而失败。
