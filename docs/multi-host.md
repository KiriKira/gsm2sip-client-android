# 多主机连接同一备用机

每台主机用独立的 client 配对码加入同一个 owner；备用机仍只配对一次。
在服务器上为每台新增主机重复生成一次性配对码：

```sh
gsm2sip-admin pairing-code create --owner-id OWNER_UUID --role client --ttl 10m
```

不要复制另一台主机的 access/refresh token 或 SIP 密码。每个配对安装拥有自己的设备 UUID、会话、SIP endpoint/AOR、短信回执与本地缓存。Android 配对请求声明 `platform=android`；平台字段只是展示标签。

概览的“已配对主机”显示同账号的设备、平台、配对状态及“此主机”。配对状态不代表当前在线。列表缓存按本机配对身份隔离，离线或折叠重建时可显示上次结果；列表暂时不可用不会阻断短信/网关刷新。旧服务器返回 404 时显示不支持该列表。

短信按 owner 共享：每台主机都能看到远端 SIM 的收件和发送任务，但各自持久化游标并在本地提交后确认。另一台主机确认不会删除服务器保留的事件。两台主机分别主动发送相同文本属于两个请求，不跨设备合并成一个任务。

来电在服务端建立当时可授权设备的候选快照，各台主机使用不同唤醒 nonce。完成注册和 ready 只是准备振铃；实际认证 SIP 通道接通后才决定唯一赢家。其他候选终止并显示“另一台主机已接听此来电”。一台拒接、撤权或暂时未注册不会直接拒绝其他候选；新配对的设备从下一通来电开始参加。

备用机仍只占用一个蜂窝通话位置。各台主机可以申请呼出，但同时申请时只有一台获得意图，其他台收到 busy；不会自动换 SIM、重复拨号或由本机运营商拨号。当前不提供通话中途从一台主机转交到另一台的功能。

WSS 只是同步提示。短信变化可提示同 owner 的所有主机；来电参与者事件只提示对应主机。已启用的通话服务会响应提示并立即查询自己的通话状态，保留周期查询作为恢复途径。只开后台语音而未开短信连接时仍用通话服务的 HTTPS 轮询。网络中断、Doze、force-stop 和未实现的 FCM/ICE/TURN 限制仍适用。

Windows 或其他平台可复用同一 HTTPS/WSS/SIP 契约，必须独立配对、独立本地持久化并验证 TLS/SRTP。服务端接受开放平台标签；Windows 的 UI、音频与后台集成仍待实现。
