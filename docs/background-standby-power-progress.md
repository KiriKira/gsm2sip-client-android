## 已实施的客户端部分

| 对应计划 | 实现 | 默认行为 |
| --- | --- | --- |
| 观测 / A1 | `StandbyDiagnostics` 在内存聚合 HTTP 次数、失败与耗时；统一 `ServerCapabilities` 响应，节点探测不重复请求能力 | 开启；计数仅包含固定类别与原因，不保存 URL、ID、令牌或正文；字节数、电量与端到端时间尚未采集 |
| A2 | 先处理事件和通知，再刷新网关/SIM；元数据失败不阻断事件接收；内容未变避免重复写入 | 元数据刷新最短间隔 30 秒；实验构建为 5 分钟；首次/节点切换缺少缓存时仍查询 |
| A3 | SQLite 保存成功 ACK 的不透明游标，按节点和配对隔离；失败 ACK 保留重试，重启后继续去重 | 开启；已检索服务端 `confirmed_at` 使用处，目前只见存储、响应与测试，不承担在线资格续租 |
| A4 | 同步期间的新请求合并为一轮待执行补查，排队执行避免饿死通知任务；节点探测使用有限执行队列 | 开启；v1 的 call 提示继续同时补查短信，来电控制先触发 |
| A5 | 记录实际/原始推送优先级；补 `onDeletedMessages()`；普通优先级或后台服务启动失败转为 JobScheduler 所拥有的短信恢复任务 | 开启；任务完成认证拉取、持久化与通知后结束；遵守用户停止/会话变更；不能保证秒级来电 |
| B1 | 无默认网络时跳过短信请求与 WSS 建连；网络恢复触发同步；独立的下一次周期调度支持失败退避 | 默认仍为 30 秒；更长周期和失败退避仅实验启用 |
| B2 的续租去重 | 同一配对的成功 RTC 能力续租在 15 秒内共享，失败不缓存，禁用立即提交并清缓存；工作锁按会话独立 | 开启；保留原 90 秒资格约束；备用节点健康探测周期尚未放宽 |
| B3 实验 | 可关闭客户端主动 Ping，依靠现有服务端 Ping/Pong | 默认维持客户端 25 秒 Ping；实验开关关闭它；黑洞网络验收尚未完成 |

JobScheduler 恢复任务直接读取事件并投递通知，不把一次失败的前台服务启动无限重复。通知被禁止时保留持久化通知队列，等待后续可用机会；不为权限未恢复而持续主动重试。任务采用网络约束与系统指数退避，不承诺固定投递时间。普通优先级来电提示可以唤醒已经运行的来电服务，不绕过后台启动限制新建服务。

会话网络工作锁使用按活跃调用计数释放的独立锁，避免全局网络锁或哈希分桶碰撞阻塞健康节点。成功 RTC 续租响应缓存限制为 128 项，淘汰只会增加一次请求，不会延长服务器租约。

## 实验开关

默认构建：

```sh
bash gradlew :app:assembleDebug
```

实验构建（仅供对照验证）：

```sh
bash gradlew :app:assembleDebug -PstandbyExperiments=true
```

`BuildConfig.STANDBY_EXPERIMENTS` 默认 `false`。开启后同时启用：元数据 5 分钟刷新、已打开 WSS 的短信兜底 120 秒、空闲同步失败退避至 300 秒、关闭客户端主动 Ping。当前组合用于建立初步对照，出现问题时应拆分变量测试；不能把它当作已验收的发布设置。通知失败重试仍使用原来的 30 秒常量。

## 尚未实施/未达到的门槛

- A4 的 v2 scopes、wake_id 与精确分流：需要服务端和 Kyubey 协议一起版本化，当前保留 v1 双路获取。
- A5 的全部端到端生命周期与目标厂商策略验证；当前系统恢复任务不是实时来电的替代方案。
- B2 的完整多节点健康/历史状态独立调度，以及前台/后台请求结果共享。
- B3 的 NAT/VPN、上下行黑洞检测；因此默认不关闭主动 Ping。
- C0～C3：中继 TTL、真实设备确认、可休眠来电候选规则、新协议待机状态机、释放持续信令锁与减少常驻连接，均待跨仓库实施。
- C4 AndroidConfigV2 是观察项，未引入预览 API。
- 真机的 8 小时 × 3 轮耗电、随机呼入、Doze 与厂商后台限制验收。

这些项目不算完成。当前分支保留原来电唤醒锁，未发布或部署。推进推送休眠阶段前，须按计划先收集第一批功能与功耗基线；当前 `adb devices -l` 没有设备，无法在本环境完成真机验收。服务端和 Kyubey 工作区/部署尚未改动。
