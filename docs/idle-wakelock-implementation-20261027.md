# 持续待机唤醒锁修复实施记录

2026-10-27；对应 [修复计划](idle-wakelock-fix-plan-20261027.md)。

## 第一批客户端改动

- 信令物理锁由独立所有者 token 管理：兼容待机、真实通话、一次控制补查；工作完成只能释放自己的所有权。关闭引擎使迟到获取无效；各所有者及物理锁都有超时，换节点互不释放。
- 导出和设置摘要增加各持锁原因、同步数据阶段、推送登记耗时。原因允许重叠，不能相加当成物理持锁总时间；原因区间按截止时间计。
- RTC 调度统一合并 WSS、网络、推送提示：一次在途补查最多一个尾随补查，取消旧定时器不会误取消运行中的请求，关闭后迟到提示无效。
- 短信数据同步和通知落盘完成就释放 `host-sync`，后续机会性的推送登记不延长它。
- 设置新增默认关闭的“故障退避省电（试验）”：同一引擎连续失败至少三次且没有真实通话时释放兼容待机所有权；成功立即恢复兼容所有权。其他节点可继续持锁。相同网络内服务器恢复可能等到手机再次可执行才重连，界面明确提示。该设备试验配置不进入完整备份。

这批改动仍保留正常在线的兼容待机锁，**尚未解决健康在线待机的小时级持锁**。没有将仅登记成功当成 FCM 可达，也没有启用会受 90s 候选资格限制的健康在线无锁 WSS 试验。服务端休眠资格、推送队列和客户端推送休眠是后续独立工作包。

## 验证

新增四个现实风险回归：补查完成不释放真实通话、空闲所有者释放不打断在途补查、提示突发合并及关闭后不复活、无 FCM 失败释锁与成功恢复。复用原有暂停/恢复/换节点/超时和断网恢复测试。

按用户要求不在本地构建 APK，构建、测试和 lint 交 PR CI。文档/差异格式检查通过；真机同窗口锁归因、Doze 来电和耗电对照尚待执行，不能声称已实测节电。

## 第二批：完成现有协议下的客户端收口

用户确认：服务端先保留计划，本轮不实现；不生成本地 APK，不做真机验收。

- **推送交接**：有效配对的提示按会话和 CALL/SYNC 通道合并，使用最多 15s 的 `push-handoff` 桥接锁。启动拒绝立即释放，消费者先获取自己的锁再接管；旧请求不能释放新提示的所有权。普通优先级只唤醒已有服务或交给已有系统恢复任务，不取得新的启动豁免。
- **启动时提示**：呼叫服务初始化期间暂存一次提示，引擎就绪后处理；启动准备也使用有截止时间的工作锁与网络预算。关闭/换会话后不重新声明旧资格。
- **请求预算**：RTC 补查、用户控制操作与启动准备使用 15s 总预算；同步使用现有总截止时间。预算传入连接/读取超时、认证/资格锁等待和后续请求，截止或引擎关闭会主动断开在途 HTTP；不只等待唤醒锁自动到期。系统 DNS 或底层 I/O 的取消仍取决于 Android 网络实现，不能承诺强制终止任意系统调用。
- **实际工作统计**：响铃与媒体通话分别归因。推送登记阶段统计移到实际异步执行处，登记任务合并并使用独立 60s 预算，不占用短信同步锁。只记录有效配对的 FCM 接收，并按匿名节点区分；未配对提示不算投递证据。
- **终态清理**：活跃 ID 不在列表时单独读取确认，404 才结束本地状态；不会把分页/截断当成挂断。过期邀请不重新响铃。媒体插入与终态更新互斥，防止已结束通话遗留媒体；本地挂断/拒接提交失败也清理本地媒体，不永久停留在快轮询。终态完整快照及时丢弃，轻量终态去重保留一小时。
- **节点维护**：短时间内已有同会话、同网络路径的成功 RTC 请求时复用可达性和 RTT，健康探测省去重复 capabilities 请求；仍独立查询网关状态，不把客户端 HTTP 成功冒充 Homura 在线。证据仅在内存保存、15s 后过期，不逐轮询写库。
- **偏好与代际**：引擎每轮确认会话和接听意愿。关闭接听后真实通话继续到终态；没有真实通话时停止声明资格和空闲请求。退避释锁试验仍默认关闭。
